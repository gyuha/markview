A01  툴바에 `[data-agent-toggle]` 버튼이 하나 있고 시작 직후 `aria-pressed`가 "false"이며 패널(`[data-agent-panel]`)은 보이지 않는다. 시작·탭 전환만으로는 `detect_agents`와 `run_agent`가 불리지 않는다
A02  버튼을 누르면 패널이 보이고 `aria-pressed`가 "true"가 되며 `detect_agents`가 정확히 1번 불린다. 닫았다 다시 열어도 추가 호출이 없다
A03  프리셋 목록(`[data-agent-preset]`)은 찾은 에이전트만 고를 수 있고 못 찾은 것은 비활성이다. 하나도 못 찾았으면 보내기가 비활성이고 안내가 보인다
A04  지시문(`[data-agent-prompt]`)이 비어 있거나 공백뿐이면 보내기(`[data-agent-send]`)가 비활성이다
A05  보내기를 누르면 `run_agent`가 정확히 1번 `{ preset, prompt, text, path }`로 불린다. `text`는 그 순간 활성 탭의 원문이고 `path`는 그 탭 경로다. 실행 중에는 보내기가 비활성이고 취소(`[data-agent-cancel]`)가 보인다
A06  `agent-log` 이벤트의 줄이 그 경로 탭의 로그(`[data-agent-log]`)에만 쌓이고 다른 탭 로그에는 보이지 않는다
A07  취소를 누르면 `cancel_agent`가 정확히 1번 `{ path }`로 불리고, 실행이 "취소했습니다"로 끝나면 오류 표시 없이 보내기가 다시 활성이 된다
A08  실행이 오류로 끝나면 패널에 오류 글자가 보이고 보내기가 다시 활성이 되며 문서 원문과 수정됨 표시는 그대로다
A09  실행이 끝나면 diff(`[data-agent-diff]`)에 삭제 줄과 추가 줄이 보이고 수락(`[data-agent-accept]`)·거절(`[data-agent-reject]`)이 있다. 이 시점의 원문은 아직 바뀌지 않았다
A10  분할 모드에서 수락하면 원문이 결과와 같아지고 CodeMirror 문서도 같으며 수정됨 표시가 켜지고 diff가 사라진다
A11  편집 모드(Muya)에서 수락하면 원문이 결과와 같아지고 Muya가 내보내는 마크다운도 결과와 같으며 수정됨 표시가 켜진다
A12  거절하면 원문과 수정됨 표시가 그대로이고 diff가 사라진다
A13  실행 중 같은 탭의 문서를 고치면 결과가 와도 수락이 비활성이고 "바뀌었습니다" 안내가 보이며, 결과 버리기(`[data-agent-discard]`)와 다시 실행(`[data-agent-rerun]`)이 있다. 다시 실행은 그 시점의 원문으로 `run_agent`를 부른다
A14  결과가 보낸 원문과 같으면 "변경 없음" 안내가 보이고 수락이 비활성이다
A15  한 탭이 실행 중이어도 다른 탭의 보내기는 활성이고 독립으로 실행된다. 실행 중이던 탭으로 돌아오면 그 탭의 실행 상태가 남아 있다
A16  실행·수락·거절 어느 단계에서도 `write_markdown`은 불리지 않는다
A17  실행 중인 탭을 닫으면 `cancel_agent`가 그 경로로 정확히 1번 불린다
A18  분할 모드에서 글자를 고르고 패널을 누르면 `[data-agent-selection]`에 그 글자가 보이고, 선택이 없으면 보이지 않는다
A19  편집 모드(Muya)에서도 글자를 고르고 패널을 누르면 `[data-agent-selection]`에 마크다운 원문 그대로 보이고, 선택이 없으면 보이지 않는다
A20  선택이 있으면 `run_agent`의 `prompt`가 `<선택>`…`</선택>`으로 선택 원문을 담고 그 뒤에 사용자 지시가 오며, 선택이 없으면 `prompt`는 사용자 지시 그대로다
A21  선택 해제(`[data-agent-selection-clear]`)를 누르면 미리보기가 사라지고 다음 실행의 `prompt`가 사용자 지시 그대로다
A22  빠른 액션 칩(`[data-agent-chip]`)이 4개 보이고 각각 이름이 있다
A23  칩을 누르면 지시 입력창이 그 칩의 문장으로 채워지고 보내기가 활성이며 `run_agent`는 아직 불리지 않는다
A24  실행 중에는 칩이 모두 비활성이다
B01  설정 창에 "에이전트" 탭이 있고, 그 안의 빠른 액션 목록(`[data-qa-row]`)은 처음에 기본 4개이며 이름이 패널의 칩과 같다. 설정을 열기만 해서는 `detect_agents`가 불리지 않고, "에이전트" 탭을 보면 불린다
B02  빠른 액션 이름을 고치면(`change`) 열려 있는 패널의 칩 이름이 바뀌고 저장소에 남으며, 같은 저장소를 쓰는 새 창에서도 고친 목록이 나온다
B03  추가(`[data-qa-add]`)하면 행과 칩이 하나 늘고, 삭제(`[data-qa-delete]`)하면 줄며, 모두 지우면 칩이 하나도 없고 이것도 새 창에 남는다
B04  이름이나 문장을 비운 채 저장하려 하면 오류(`[data-qa-error]`)가 보이고 저장소와 칩은 그대로다
B05  "기본값으로 복원"(`[data-qa-reset]`)을 누르면 기본 4개로 돌아가고 칩도 같아진다
B06  고친 문장이 칩을 눌렀을 때 지시 입력창에 채워진다
B07  설정 창의 CLI 경로 목록(`[data-cli-row]`)에 프리셋 3개가 있고, 찾은 것은 경로를, 못 찾은 것은 "없음"을 보인다
B08  "다시 찾기"(`[data-cli-refind]`)를 누르면 `detect_agents`가 `{ refresh: true }`로 정확히 1번 불린다
B09  경로를 입력하고 지정(`[data-cli-set]`)하면 `set_agent_path`가 `{ preset, path }`로 정확히 1번 불리고, 성공하면 목록과 패널의 프리셋 선택이 새 결과를 따른다
B10  `set_agent_path`가 거부되면 그 행에 오류(`[data-cli-error]`)가 보이고 경로 표시는 그대로다
B11  입력을 비우고 지정하면 `set_agent_path`가 `path: ""`로 불린다(지정 지우기)
P01  설정 창에 "프로바이더" 탭이 있고 그 안에 provider 행(`[data-provider-row]`)이 claude·codex·opencode 3개 있다
P02  행마다 활성 토글(`[data-provider-enabled]`)이 `role=switch`이고 처음엔 `aria-checked`가 "true"이며, 끄면 `set_provider_settings`가 `{ preset, enabled: false }`로 정확히 1번 불리고 `aria-checked`가 "false"가 된다
P03  비활성 provider는 열려 있는 패널의 프리셋 선택에서 고를 수 없게 되고(선택값도 다른 provider로 옮겨 감), 전부 비활성이면 보내기가 비활성이고 안내(`[data-agent-empty]`)가 보인다
P04  모델 입력(`[data-provider-model]`)을 저장하면 `set_provider_settings`가 `{ preset, model }`로 정확히 1번 불리고, 거부된 값(공백 포함·`-` 시작)은 행의 오류(`[data-provider-error]`)가 보이며 입력이 저장된 값으로 돌아간다
P05  설정을 열고 프로바이더 탭을 보는 것만으로는 `provider_diagnostic`이 불리지 않고, "버전 확인"(`[data-provider-diagnose]`)을 누르면 `{ preset }`로 정확히 1번 불리며 결과(버전 또는 오류)가 행에 보인다
P06  "연결 시험"(`[data-provider-test]`)은 누르기 전에는 `test_provider`가 불리지 않고, 누르면 `{ preset }`로 정확히 1번 불리며 진행 중에는 비활성이고 끝나면 결과(OK 또는 실패 이유)가 행에 보인다
P07  CLI 경로 지정·다시 찾기(`[data-cli-row]`·`[data-cli-refind]`)는 프로바이더 탭 안에 있고, "에이전트" 탭에는 빠른 액션(`[data-qa-row]`)만 있고 CLI 경로(`[data-cli-row]`)는 없다
P08  패널에서 실행할 때 `run_agent` 인자의 키는 정확히 `path`·`preset`·`prompt`·`text` 네 개뿐이다(저장된 모델이 있어도 모델·경로·명령을 웹뷰가 넘기지 않는다)
P09  설정 창에서 provider를 껐다 켜면 패널을 다시 열지 않아도 같은 창의 패널 선택 목록이 바로 따라 바뀐다
P10  provider 행의 토글과 버튼(버전 확인·연결 시험·지정)은 네이티브 `<button type="button">`이고 비활성이 아니며 포커스를 받을 수 있다
Q01  보내자마자(`run_agent`가 아직 끝나지 않았어도) 상태 줄(`[data-agent-status]`)이 보이고 "실행 중"·선택한 프로바이더 이름·경과 시간(`00:0n`)·현재 단계("요청을 보내는 중")가 들어 있다
Q02  경과 시간은 시간이 지나면 늘어난다(1초 넘게 기다린 뒤의 값이 처음보다 크다)
Q03  `agent-log` 이벤트 `{ kind: "tool", line }`은 출력 상자(`[data-agent-log]`)에 `data-kind="tool"` 줄로 쌓이고 상태 줄의 현재 단계가 그 줄의 글자로 바뀐다. `thinking`·`status`도 같다
Q04  `kind`가 없는 줄은 `data-kind="raw"`로 쌓이고, `message`는 `data-kind="message"`로, 오류는 `data-kind="error"`로 구별된다. 바로 앞 줄과 똑같은 줄은 더해지지 않는다
Q05  보낸 지시는 출력 상자 맨 위에 `data-kind="user"` 줄로 보이고, 그 아래에 "…에 요청을 보냈습니다" 줄이 따른다
Q06  실행이 끝나면 상태 줄이 "완료"로 바뀌고 경과 시간이 더는 늘지 않는다. 오류로 끝나면 "실패", 취소하면 "취소됨"이 된다
Q07  다른 탭으로 갔다 와도 그 탭의 출력 줄과 상태 줄(경과 시간이 계속 흐름)이 그대로 있고 다른 탭의 출력은 섞이지 않는다
Q08  입력 상자에서 Enter를 누르면(Shift 없이, 글자 조합 중이 아닐 때) 보내기를 누른 것과 같이 `run_agent`가 1번 불리고 입력 상자가 비워진다. Shift+Enter는 보내지 않고, 조합 중(`isComposing`)의 Enter도 보내지 않으며, 입력이 비어 있으면 아무 일도 없다
Q09  실행이 실패하거나 취소되면 보낸 지시가 입력 상자로 되돌아와 고쳐서 다시 보낼 수 있고, 성공해서 검토 단계로 가면 입력 상자는 빈 채로 있다
Q10  복사(`[data-agent-copy]`)를 누르면 클립보드 쓰기가 출력 상자의 글(지시 `> …`와 모든 단계·답)로 정확히 1번 불리고 단추가 "복사됨"이 된다. 출력이 없으면 단추가 비활성이다
Q11  다시 실행은 입력 상자가 비어 있어도 직전에 보낸 지시로 `run_agent`를 부른다
R01  패널에 자동 수락 체크박스(`[data-agent-autoaccept]`)가 있고 처음엔 꺼져 있으며, 켜면 저장소 키 `markview.agent.autoaccept`가 "true"가 되고 같은 저장소를 쓰는 새 창에서도 켜진 채로 보인다
R02  켜 둔 채 변경이 있는 결과가 오면 수락을 누르지 않아도 원문이 결과와 같아지고 수정됨이 켜지며, diff와 수락·거절 단추는 나타나지 않고 출력 상자에 "자동으로 수락" 줄이 남는다. 이때도 `write_markdown`은 불리지 않는다
R03  꺼 둔 채 결과가 오면 지금처럼 diff와 수락·거절이 나오고 원문은 그대로다
R04  켜 둬도 실행 중에 같은 탭의 문서가 바뀌었으면 자동으로 수락하지 않고 '바뀌었습니다' 안내와 버리기·다시 실행이 나오며, 결과가 보낸 원문과 같으면(변경 없음) 안내만 나오고 수정됨은 그대로다
R05  편집 모드(Muya)에서도 자동 수락이 원문과 Muya 마크다운을 결과로 바꾼다
U01  두 번째 전송 뒤에도 첫 전송의 출력(지시·단계·답)이 출력 상자에 그대로 남고, 새 지시(user 줄)가 그 아래에 쌓인다
U02  이어서 보낼 때도 `run_agent` 인자의 키는 정확히 `path`·`preset`·`prompt`·`text` 네 개뿐이다(대화는 Rust가 이어 준다)
U03  "새 대화"(`[data-agent-new]`)는 출력이 있을 때만 보이고 실행 중에는 비활성이며, 누르면 `reset_agent_session`이 `{ path }`로 정확히 1번 불리고 출력과 상태 줄이 비워진다. 그 뒤 첫 전송의 출력에는 이전 전송이 없다
U04  탭을 닫으면 `reset_agent_session`이 그 탭의 경로로 불린다(임시 폴더 정리)
U05  프로바이더를 바꿔서 보내면 출력에 "새 대화로 시작합니다" 줄이 나오고, 같은 프로바이더로 보내면 나오지 않는다
V01  사용자가 보낸 질의는 출력 상자에서 말풍선(`[data-kind="user"]`)으로 보인다 — 배경색이 있고(투명이 아님) 모서리가 둥글며, 에이전트의 단계·답 줄(`tool`·`message`·`status`)은 배경이 투명하다
V02  말풍선 아래에 시각(`[data-agent-time]`)이 "토요일 오전 12:53"처럼 요일과 오전/오후 시:분으로 보인다
V03  복사 아이콘(`[data-agent-entry-copy]`)을 누르면 클립보드 쓰기가 그 질의의 글 하나만으로 정확히 1번 불리고 아이콘이 잠시 복사됨(`data-copied`) 표시가 된다
V04  "입력 상자로 되돌리기" 아이콘(`[data-agent-entry-redo]`)을 누르면 그 질의가 입력 상자에 채워지고 입력 상자에 포커스가 간다. 실행 중에는 비활성이다
V05  에이전트의 답(`message`) 줄에도 복사 아이콘이 있고 누르면 그 답의 글만 복사된다
V06  질의가 여러 개일 때 말풍선은 보낸 순서대로 각자 자기 질의의 글을 담고, 복사와 되돌리기는 눌린 말풍선의 질의에만 적용된다
