# 마크다운 파싱은 프론트엔드에서 한다

Tauri 마크다운 뷰어에서 마크다운 → HTML 변환은 Rust가 아니라 프론트엔드(markdown-it/remark 계열)에서 수행한다. Rust는 파일 경로와 바이트만 다루고, 파싱·mermaid 렌더·코드 하이라이팅은 모두 같은 JS 런타임에서 처리한다.

검증해야 할 리스크(mermaid 렌더, 테마 전파, 드롭 경로 수신, 탭 다중 문서)가 전부 프론트엔드 관심사인데, 파싱을 Rust로 보내면 붙는지 확인할 표면에 IPC 경계가 하나 더 늘어난다. 반대 방향의 비용도 비대칭이다 — 프론트에서 시작해 성능이 부족하면 파싱만 Rust로 옮기면 되지만, Rust로 시작한 뒤 KaTeX·각주·TOC 같은 확장이 필요해지면 Rust 확장 작성 또는 파이프라인 전면 재배치가 된다.

## 감수하는 결과
- 대용량 문서에서 파싱이 메인 스레드를 막을 수 있다. Web Worker 분리는 지금 도입하지 않고, 실제로 느릴 때 넣는다.
- HTML sanitize 책임이 프론트엔드에 남는다 (raw HTML 허용 여부는 별도 결정).
