# 색상 테마는 선택 테마 위에 얹고, 라이트용·다크용을 따로 저장한다

`themes/*.yaml` 112개를 고를 수 있게 하되, 기존 선택 테마(`light`/`dark`/`system`)는 없애지 않는다. 색상 테마는 **실효 테마별로 하나씩**(라이트용 1개, 다크용 1개) 저장하고, 실효 테마가 정해지면 그 쪽 색상 테마가 적용된다. YAML의 `details`(`lighter` 32개 / `darker` 80개)가 라이트용·다크용 분류 기준이다.

단일 색상 테마 하나만 고르게 하는 쪽이 더 단순하지만, 그러면 `system` 모드(OS 외관 추종)가 사라지고 ADR `260824-224840`이 보호하는 네이티브 테마 해제 동작이 무의미해진다. 쌍으로 저장하면 `system`이 "OS가 밝으면 라이트용, 어두우면 다크용"으로 그대로 살아남는다. 저장 키가 둘로 늘어나는 것이 대가다.

YAML은 실행 중에 읽지 않고 빌드 때 `scripts/gen-themes.mjs`가 TS 모듈로 굽는다. webview 권한을 최소로 유지하는 방침(ADR `261010-234732`)과 맞추기 위해서다.
