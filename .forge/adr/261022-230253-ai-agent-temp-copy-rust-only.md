# AI 에이전트는 Rust가 임시 복사본에서 실행하고, 수락한 결과만 문서에 반영한다

문서 편집용 AI 에이전트(Claude Code, Codex, OpenCode의 로컬 CLI)를 붙이면서, 에이전트가 **원본 파일을 직접 고치게 하지 않고** 현재 편집 버퍼를 임시 폴더에 쓴 사본에서 돌리기로 했다. 자식 프로세스 실행은 **Rust 커맨드만** 한다. 웹뷰는 프리셋 id·지시문·버퍼 텍스트만 넘기고, 실행 파일 경로나 인자는 넘기지 않는다. `src-tauri/capabilities/default.json`에는 shell/fs/http 권한을 추가하지 않는다 (`261010-234732-webview-minimal-capabilities.md`의 연장).

이 앱은 raw HTML을 허용하고 DOMPurify로 거른다(`260822-222214-raw-html-sanitized.md`). 그 걸러내기가 뚫리는 경우를 가정하면, 웹뷰가 임의 명령이나 임의 경로를 실행시킬 수 있는 통로가 있으면 안 된다.

## 결정
- **원본은 수락 전까지 바뀌지 않는다.** 에이전트 실행이 끝나면 앱이 사본을 읽어 원본과 diff로 보여 주고, 사용자가 수락한 경우에만 기존 저장 경로(`write_markdown`의 읽은 경로만 허용 + 수정 시각 충돌 감지)로 쓴다. 쓰기 범위 보장을 CLI별 권한 플래그에만 맡기면 CLI 4개 × 버전마다 바뀌는 옵션을 계속 검증해야 한다. 임시 사본은 CLI와 무관하게 "내 문서가 몰래 바뀌지 않는다"를 같은 코드로 보장한다. 플래그는 보조 수단이다.
- **저장 안 한 변경도 에이전트가 본다.** 디스크의 원본이 아니라 현재 편집 버퍼를 넘기기 때문이다.
- **CLI 실행 파일은 고정 이름 3개만 찾는다.** 로그인 셸(`$SHELL -ilc`)이 만드는 `PATH`를 읽어 그 안에서 찾고(GUI 앱은 셸 `PATH`를 상속하지 않고, mise 등은 `.zshrc`가 `PATH`를 만들며 버전별 경로에 설치된다), 실행할 때도 그 `PATH`를 넘긴다(`#!/usr/bin/env node` 스크립트가 `node`를 찾아야 한다), 수동 경로는 **파일명이 프리셋 이름과 일치할 때만** 받는다. 사용자가 입력한 명령 템플릿은 받지 않는다 — 설정 문자열이 곧 실행 명령이 되면 웹뷰가 뚫렸을 때 임의 명령 실행이 된다.
- **실행 중 문서가 바뀌면 병합하지 않는다.** 시작 시점 원문(스냅샷)을 기억해 두고, 결과가 왔을 때 현재 원문과 같을 때만 수락을 허용한다. 다르면 결과 버리기 또는 다시 실행만 준다.
- **diff는 패널 안에서 소스 diff로 보여 준다.** 편집 모드(Muya)는 WYSIWYG이라 소스 줄 단위 인라인 diff를 끼울 수 없고, `vendor/muya`는 원본 대조(`scripts/check-muya-vendor.mjs`)로 고정돼 있다.

## 버린 대안
- **Gemini CLI 프리셋** — 처음 합의에는 있었으나, 실기기 확인에서 이 기기의 Google 계정이 `IneligibleTierError`(Gemini Code Assist for individuals 지원 종료)로 인증에 실패해 사본을 고치는지 확인하지 못했다. 확인하지 못한 어댑터를 출시하지 않는다는 판단으로 사용자가 제외했다. 인증이 되는 환경에서 확인되면 `PRESETS`에 어댑터 한 줄과 시험을 더해 되살릴 수 있다.
- **원본 파일을 에이전트가 직접 수정 + 변경 감지** — 구현은 가장 작다. 그러나 저장 안 한 변경을 에이전트가 못 보고, 이미 되돌릴 수 없게 쓰인 뒤에야 수락/거절을 묻게 되며, 쓰기 범위가 CLI 플래그에만 달린다.
- **Anthropic API 직접 호출** — 에이전트 쓰기 범위는 정확히 한정되지만 API 키 저장·과금이 생기고, 도구 호출 루프를 직접 만들어야 한다. 사용자는 이미 로컬 CLI와 구독을 쓴다.
- **ACP(Agent Client Protocol)·MCP 서버** — 마크다운 뷰어에는 구현량이 크거나, 사용자가 에이전트를 따로 띄워야 한다.
- **사용자 정의 명령 템플릿** — 임의 명령 실행 통로가 열린다.

## 감수하는 결과
- 임시 사본에는 문서 옆의 상대 경로 이미지(`assets/`)가 없어서 에이전트가 이미지를 볼 수 없다. 텍스트 편집에는 영향이 작다.
- 에이전트 프로세스가 임시 폴더 밖 파일을 쓰는 것은 앱이 막지 못한다. 그 부분은 CLI별 샌드박스·권한 옵션이 보조한다. 이 ADR이 보장하는 것은 **문서 파일**이 수락 단계를 거친다는 것까지다.
- CLI 3개의 실제 동작(옵션, 출력)은 자동 테스트로 보장할 수 없어 실기기 확인이 필요하다. 가짜 CLI 스크립트로 앱 쪽 계약만 시험한다.
- 실행에 걸리는 수십 초~수 분 동안 사용자가 문서를 고치면 결과를 수락할 수 없고 다시 돌려야 한다.
