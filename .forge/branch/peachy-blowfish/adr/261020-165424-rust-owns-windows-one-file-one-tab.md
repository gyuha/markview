# 다중 창: 창 생성과 소유 창 목록은 Rust가 맡고, 한 파일은 앱 전체에서 한 탭만 둔다

탭 분리·병합(이슈 #11)으로 창이 여러 개가 되면서 두 가지를 정했다. 첫째, **창 생성과 "어느 창이 어느 파일을 열었는지"(소유 창) 목록은 Rust가 관리**하고 웹뷰에는 창 생성 권한을 열지 않는다 — 웹뷰 권한 최소화 원칙(`261010-234732-webview-minimal-capabilities.md`)을 그대로 따른다. 둘째, **한 파일은 앱 전체에서 소유 창이 하나뿐**이다. 이미 다른 창이 연 파일을 열려고 하면 새 탭을 만들지 않고 그 창을 앞으로 가져와 탭을 활성화한다.

## 검토한 대안
- **창마다 같은 파일을 독립적으로 열기**: 뷰어로만 쓸 때는 편하지만, 한쪽이 저장하면 다른 쪽이 mtime 비교로 "외부 변경"이라 오인해 충돌 경로가 생긴다. 편집 모드가 있는 앱이라 택하지 않았다.
- **두 번째 창은 읽기 전용**: 소유권과 읽기 전용 상태를 추적해야 해서 복잡도가 가장 높다.

## 결과
- "같은 파일을 두 창에 나란히 띄워 비교하고 싶다"는 요구는 지원하지 않는다. 그 요구가 생기면 이 결정을 다시 연다.
- 미저장 탭은 창 사이로 버퍼를 옮기지 않는다. 옮기기 전에 저장을 확인하고 항상 디스크 파일 기준으로 연다.
