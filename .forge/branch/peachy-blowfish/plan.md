# 다중 창 인프라와 탭 끌어서 새 창으로 분리 (이슈 #11, part 1/2)

## 목표 / 비목표
- 목표:
  - 탭을 **탭바에서 일정 거리(약 40px) 이상 벗어난 곳**에 놓으면(창 안 본문·창 밖 바탕화면 모두) 그 커서 위치에 **새 창**이 뜨고 탭이 옮겨진다(**분리**). 새 창은 원본과 같은 크기다.
  - 이를 받치는 다중 창 인프라를 만든다: Rust가 창을 만들고 **소유 창 목록**을 관리, 한 파일은 앱 전체에서 한 탭(이미 다른 창이 연 파일은 그 창을 앞으로 가져와 활성화), 메뉴 이벤트와 닫기 가드를 창 단위로, **창 세션** 저장·복원, 테마·색상 테마·문서 너비의 창 간 실시간 동기화.
  - 미저장 탭은 옮기기 전에 "저장하고 옮기기 / 취소"로 확인한다. 옮김은 항상 디스크 파일 기준이다.
  - 끄는 동안 분리 임계를 넘으면 탭이 반투명이 되고 커서가 바뀐다(소스 창만).
- 비목표:
  - **병합**(다른 창 탭바로 끌어넣기) — part 2/2. 이 part가 끝난 시점에는 창을 나눌 수만 있고 합칠 수는 없다.
  - 항상 위(Always on top) 버튼 — 이슈 #11의 별도 plan.
  - ⌘N 새 창 메뉴, 드래그 중 창이 커서를 따라다니는 Chrome식 UX, 대상 창 탭바 강조·삽입 위치 표시.
  - 미저장 버퍼·undo 스택의 창 간 이동, 같은 파일을 두 창에 나란히 열기, 읽기 전용 창.
  - 최근 파일 목록의 실시간 동기화(열 때마다 읽으므로 불필요).
  - ⌘Q로 종료할 때의 미저장 확인(지금도 없는 기존 동작).

## 확정된 결정 (그릴링 요약)
- **범위**: 이슈의 (B)+(C)를 한 plan으로 두려다 크기 때문에 둘로 쪼갰다. (A) 항상 위는 인프라와 무관해 별도 plan(질문 1·9).
- **미저장 탭**: 옮기기 전에 저장을 확인한다. 기존 확인창(`confirmDialog`)은 2택(취소 / 확인)이라 "저장하고 옮기기"를 확인 버튼으로, "취소"를 제자리로 쓴다. 저장 후에는 디스크 기준으로 옮긴다(질문 2).
- **같은 파일**: 앱 전체에서 한 탭. 다른 창이 연 파일을 열면 그 창을 앞으로 가져와 탭을 활성화(질문 3, ADR).
- **세션**: 창별 탭 구성과 위치·크기를 복원한다. 창을 닫기 버튼(또는 마지막 탭 닫기)으로 직접 닫으면 그 창 세션이 기록에서 빠지고, ⌘Q로 닫힌 창은 남는다(질문 4·7).
- **분리 규칙**: 탭바에서 위·아래로 약 40px 이상, 또는 창 가로 범위 밖에서 놓으면 새 창. 탭바 안이면 기존 순서 바꾸기. 거리 값은 실측 후 조정(질문 5).
- **TDD**: 켬. 순수 로직(판정·세션 형식·소유 창 조회·라벨 할당·라우팅 선택)만 테스트 먼저, 창 생성·드래그는 사람이 UAT(질문 6).
- **창 생성은 Rust**: 웹뷰에는 창 생성 권한을 열지 않고 `detach_tab` 커맨드만 부른다. capability `windows`는 `main` 고정에서 `main`과 새 창 라벨 패턴으로 넓힌다.
- **메뉴 이벤트**: `handle.emit` 방송을 포커스된 창 대상 `emit_to`로 바꾼다. Finder 등 외부에서 열리는 파일은 마지막으로 포커스된 창이 받고, 창이 없으면 새로 만든다.
- **새 창 시작**: 자기에게 넘어온 파일만 열고 지난 세션 복원·`take_pending_files`는 하지 않는다(메인 창 시작 때만 한다).
- **설정 동기화**: `storage` 이벤트로 테마·색상 테마·문서 너비를 다른 창에 다시 적용한다.

## 알려진 주의사항
- **크로스 윈도우 포인터 이벤트는 증명되지 않았다**(가장 큰 위험). 지금 `pressTab`은 `window`의 `pointermove`/`pointerup`을 듣는다(`setPointerCapture`는 합성 이벤트에서 실패해 쓰지 않음). macOS에서 버튼을 누른 채 창 밖으로 나가도 이 이벤트가 계속 오는지는 [중간] 신뢰도의 추정이고 하네스로 확인할 수 없다. 작업 흐름은 중간에 사람 입력을 받을 수 없어서 **스파이크를 슬라이스로 두지 못하고 DoD 6의 ①로 옮겼다**. 안 되면 `verified: failed` → 재그릴링이다. 대안은 Rust가 드래그 중 커서를 폴링해 알려 주는 방식인데 복잡도가 크다. **fg-run 전에 `pnpm tauri dev`로 5분짜리 수동 프로브를 먼저 해 보길 권한다.**
- **window-state 플러그인과 명시 위치 충돌 가능**: 새 창에 커서 위치를 주어도 플러그인이 라벨 기준 저장값으로 덮을 수 있다. 분리로 만든 창은 생성 직후 위치를 다시 지정하거나 해당 라벨을 복원 대상에서 뺀다. 창 세션 복원(S7)에서는 반대로 라벨 복원을 그대로 쓴다.
- **세션 키 형식 변경**: 기존 하네스 S01·S06·S09는 `markview.session` 값을 직접 읽는다. 형식이 바뀌면 이 검사들이 거짓 실패(또는 통과)할 수 있어 S2에서 같은 PR 안에 같이 고친다. 이미 사용자 머신에 저장된 옛 단일 값은 `main` 창 세션으로 읽는다(S11).
- **`closeTab`의 마지막 탭 경로**는 지금 `saveSession([], null)` 뒤 창을 닫는다. 창이 여럿이면 다른 창 세션을 지우면 안 되므로 "이 창 항목만 제거"여야 한다(S2).
- **`handle.emit`은 모든 창에 방송**한다. `lib.rs`의 `emit(` 호출 7곳(메뉴 이벤트 5개, `close-requested`, `files-opened`; 작성 시점에 `grep -n "emit(" src-tauri/src/lib.rs`로 7줄 확인)을 하나도 빠뜨리지 않고 대상 창이 정해진 `emit_to`로 바꿔야 한다.
- **미저장 확인 문구**: 기존 `confirmDialog`는 "취소 / 확인" 2택이고 저장 버튼이 없다. 이 plan은 3택 컴포넌트를 새로 만들지 않고 확인 라벨을 "저장하고 옮기기"로 바꿔 쓴다. 저장이 실패하면(충돌 등) 옮기지 않고 탭을 남긴다.
- 반영 확인 시 "어느 폴더에서 앱을 띄웠는지"를 먼저 본다(지난 작업에서 반영되지 않은 빌드를 검사해 거짓 `yes`가 기록된 적이 있다).
