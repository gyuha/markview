# 요청 없이 시작하면 지난 세션의 탭을 복원하고, 설정을 모양/환경 탭으로 나눈다

## 목표 / 비목표
- 목표:
  - 앱이 열려 있던 **세션**(탭 경로·순서·활성 탭)을 탭을 열고 닫고 전환할 때마다 기록한다.
  - **요청 없이** 시작할 때(시작 시 `take_pending_files`가 빈 목록) 기록된 세션을 복원한다. 토글이 꺼져 있으면 복원하지 않는다.
  - 설정 다이얼로그를 **탭 둘("모양", "환경")** 로 나눈다. "모양"에는 지금의 모드·색상 테마가 그대로 들어가고, "환경"에는 "시작 시 지난 세션 복원" 토글 하나가 들어간다. 토글 기본값은 **켬**.
- 비목표:
  - 탭별 보기 모드(보기/분할/편집)와 스크롤 위치의 복원, 저장하지 않은 편집 내용의 복원(질문 3: 경로·순서·활성 탭만).
  - 연결 프로그램으로 열기 등 **요청이 있는** 시작에서의 복원(요청된 파일만 연다).
  - 복원하지 못한 파일에 대한 알림, 최근 파일 목록에서의 정리.
  - Rust(`src-tauri/**`)·capability·메뉴 변경. 이번 작업은 프런트엔드만 바꾼다.
  - 설정에 "모양"·"환경" 외 탭이나 다른 항목 추가.

## 확정된 결정 (그릴링 요약)
- **무엇을 연다**: 가장 최근 파일 1개가 아니라 **지난 세션의 탭 전체**(질문 1, 사용자 정정).
- **못 여는 파일**: 복원 중 읽기에 실패하는 경로는 알림 없이 건너뛰고 나머지를 연다(질문 2). 최근 파일 목록은 건드리지 않는다.
- **기억하는 것**: 탭 경로·순서·활성 탭만. 복원된 탭은 평소처럼 기본 모드로 열린다(질문 3).
- **저장 시점**: 탭을 열고 닫고 전환할 때마다 `localStorage`에 즉시 기록한다(비정상 종료에도 마지막 상태가 남는다). **토글이 꺼져 있어도 기록은 계속한다** — 토글은 복원 여부만 정한다.
- **기본값**: 토글 **켬**(질문 4). 저장된 값이 없으면 켬으로 본다. 첫 실행은 저장된 세션이 없어 빈 화면이다.
- **TDD**: 켬(질문 5).
- **복원 순서**: 저장된 순서대로 탭을 열고, 마지막에 저장된 활성 탭을 활성화한다. 활성 탭이 열리지 못했다면 열린 탭 중 마지막 탭이 활성으로 남는다.
- **복원 중에는 세션을 쓰지 않는다.** 복원이 끝난 시점에 지금 열린 탭으로 한 번 기록한다(복원 도중 중단돼도 앞선 세션을 부분 상태로 덮지 않는다). 따라서 건너뛴 파일은 복원이 끝난 세션에서 빠진다.
- **복원은 최근 파일 목록을 바꾸지 않는다.** 복원은 사용자가 새로 연 것이 아니므로 `recordRecent`를 부르지 않는다(최근 순서가 복원 순서로 뒤섞이지 않게).
- **모든 탭을 닫고 종료하면** 세션은 빈 목록이라 다음 실행은 빈 화면이다.
- **설정 탭**: 열면 항상 "모양"이 먼저 보이고 마지막 탭은 기억하지 않는다. 마우스와 ←/→ 키로 전환한다.
- **저장 키**: 세션 `markview.session`, 토글 `markview.restoreSession`(기존 `markview.theme`·`markview.recent`와 같은 방식).

## 알려진 주의사항
- **연결 프로그램으로 열기 경합**: macOS가 `RunEvent::Opened`를 프런트엔드 시작 전에 버퍼에 넣는지(그러면 `take_pending_files`가 비지 않아 복원이 건너뛰어진다) 하네스로는 증명되지 않는다. 시작 순서는 "버퍼를 비운 직후 판단"으로 두고, DoD 6의 ③(더블클릭 실행)으로 사람이 닫는다. 이 항목이 틀어지면 요청된 파일과 복원된 탭이 함께 열려 버린다.
- **복원 중 중복 열기**: 복원에서 `openPath`를 쓰면 `recordRecent`가 불리고 탭이 열릴 때마다 세션이 쓰인다. `openPath`에 "복원 모드"를 두어 두 가지를 모두 막는다(S05·S06이 고정한다).
- **하네스 페이지 간 간섭**: 최근 파일 하네스 R11은 같은 출처의 iframe(`?files=0&child=1`)을 연다. 모킹이 새 키를 지우지 않으면 부모의 세션이 자식에서 복원되어 R11이 깨진다 — 위 회고 교훈대로 시작 시 지운다(시드가 있는 페이지만 예외).
- 기본 켬이라 이 앱을 쓰던 사용자는 업데이트 후 두 번째 실행부터 복원을 겪는다. 의도한 것이다(질문 4).
- 반영 확인 시 "어느 폴더에서 앱을 띄웠는지"를 먼저 본다. 지난 작업에서 변경이 반영되지 않은 빌드를 검사해 거짓 `yes`가 기록된 적이 있다.
