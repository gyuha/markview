# 2026-08-23 — 채택 아이콘을 macOS 기하로 정규화하고 전 사이즈 파생

## 계획 vs 실제
- 계획대로 된 것: 슬라이스 4개 전부 착지. PIL 정규화 → `tauri icon` 파생 → 빌드 회귀 → 후보 정리. 아이콘 5개 파일 해시가 전부 변경됐고 빌드 검사도 유지됐다.
- 차이: 실행에는 차이가 없었다. 어긋난 것은 DoD 한 항목의 **검증 가능성**이다.

## 학습
- 다음엔 다르게:
  - **DoD 항목이 "그 작업을 실행할 환경에서" 검증 가능한지 따진다.** "Dock에서 새 아이콘 확인"을 넣었지만 `tauri dev`는 번들이 아닌 맨 바이너리를 실행하므로 Dock에 앱 아이콘이 나오지 않는다 — 원리적으로 확인 불가능한 항목을 DoD에 넣은 것이다. 확인하려면 `tauri build`로 번들해야 하고 그건 범위 밖(배포)이다. **환경이 제공하지 않는 검증을 DoD에 적으면 그 항목은 영구 미확인으로 남는다.**
  - 대신 쓸 수 있는 대체 증거: 파생물 자체를 열어 확인(마크 식별·꼭짓점 알파 0)하고, 설정이 그 파일들을 가리키는지 확인하는 것. 실패 경로가 "OS가 올바른 파일을 렌더하지 않는 것"으로 좁혀진다.
  - **"파일이 존재한다"는 DoD는 스캐폴드가 이미 만들어둔 산출물에는 쓸 수 없다.** 작업 전에 통과해버린다. 기준선 해시를 계획에 박아 **변경 여부**를 검사하는 형태로 써야 한다 — 이번 계획은 그렇게 썼고 정확히 작동했다.
  - macOS 아이콘 기하: 캔버스의 약 80%에 아트워크를 배치(바깥 여백), squircle 근사 반경은 한 변의 22.37%, 마스크는 4배로 그린 뒤 축소해 계단을 없앤다. `tauri icon`은 마스킹도 여백도 넣어주지 않는다.
