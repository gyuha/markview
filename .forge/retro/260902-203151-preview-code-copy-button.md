# 2026-09-02 — 프리뷰 코드블록에 복사 버튼 달기

## 계획 대비 실제
- 계획대로 된 것:
  - 결과물은 계획 그대로다. 일반 코드블록에만 버튼, mermaid 제외, hover 시 표시, Tauri 클립보드 플러그인, 체크 피드백. 슬라이스 6개가 순서대로 붙었고 DoD 항목이 전부 통과했다.
  - **그릴링에서 코드로 확정한 세 가지가 전부 맞았다** — mermaid에는 `<pre>`가 남지 않는다 / 재렌더가 `innerHTML`을 갈아끼우므로 위임이 유일한 선택이다 / 버튼은 sanitize 이후에 넣어야 한다. 추측으로 적었다면 실행 중에 하나씩 부딪혔을 것들이다.
  - 워크플로 대신 직접 실행 판단이 맞았다. 슬라이스가 S1→S6로 거의 완전한 순차 의존이라 병렬화할 것이 없었다.
- 발산:
  - **변이 3개 중 2개가 결함을 만들지 못했다.** 검사의 실패가 아니라 변이 설계의 실패였다 (→ ADR로 승급).
  - **계획이 공유 픽스처(`mock-tauri.js`의 `DOC.text`)를 고치라고 적었는데, 그러면 `toolbar` 하네스가 깨진다.** 실행 중에 발견해 `scroll`의 문서 주입 방식으로 바꿨다 (→ ADR로 승급).
  - 아이콘을 CSS `mask` + data-URI로 만들었다가 인라인 SVG로 되돌렸다. 기능은 같고 저장소에 선례가 있는 쪽을 택했다.
  - UAT 전에 `pnpm tauri build`를 한 번 돌린 것은 계획에 없던 추가 검증이었는데 값을 했다 — capability 권한 문자열은 `cargo check`가 검증하지 않고 `tauri build`가 스키마로 잡는다.

## 배운 것
- 다음엔 다르게:
  - **계획 단계에서 변이를 적을 때, 그 변이가 무엇을 관측 가능하게 바꾸는지까지 함께 적는다.** 이번 계획은 "변이 A: `pre.textContent`로 바꾸면 버튼 텍스트가 섞여 깨져야 한다"라고 적었는데, 그 시점엔 아이콘이 SVG일지 텍스트일지 정해지지 않았었다. **변이의 유효성은 구현 세부에 의존하므로, 구현이 정해지기 전에 확정한 변이는 빗나갈 수 있다.** 변이 목록은 계획에서 후보로 적되 실행 시점에 재검토한다.
  - **계획에 공유 자원을 고치라고 적기 전에 그 자원의 소비자를 먼저 센다.** `DOC.text`가 몇 개의 하네스에 쓰이는지는 그릴링 중 `grep` 한 번이면 알 수 있었다. 확인하지 않아 계획이 위험한 지시를 담았다.
  - **`tauri build`는 `cargo check`가 못 잡는 것(capability 스키마)을 잡는다.** Tauri 권한을 건드리는 작업의 DoD에는 `cargo check`만이 아니라 `tauri build`를 넣는다. 권한 이름 오타는 컴파일도 타입 검사도 통과하고 런타임에만 거부된다.
  - 새 CSS 메커니즘(mask/data-URI)을 도입하기 전에 저장소에 선례가 있는지 본다. 이번엔 되돌리는 비용이 작았지만, 더 늦게 발견했다면 스타일 체계가 두 갈래로 갈렸을 것이다.
- 확인된 것:
  - **픽스처에 "같은 종류의 여러 변형"을 넣는 것이 결정적이었다.** 변이 A′(하이라이팅 마크업 유출)는 **언어 있는 블록에서만** 잡혔다 — 언어 없는 블록만으로 검사했다면 그대로 통과했다. 회고 `260825-071611`의 "픽스처가 상태에 도달해야 한다"의 연장선이고, 여기서는 "상태 하나가 아니라 변형들에 도달해야 한다"였다.
  - **변이 C가 예상보다 강하게 잡혔고(6건), 그 초과분이 정보였다.** 계획은 "재렌더 후 깨짐"을 예상했는데 첫 클릭부터 깨졌다 — `installCopyHandler()`가 `DOMContentLoaded`에 도는데 그때는 탭이 없어 리스너가 0개 붙기 때문이다. 위임이 재렌더뿐 아니라 초기 타이밍 문제까지 함께 해결하고 있었다는 뜻이고, 이건 계획에 적혀 있지 않았다.
  - ADR을 **작업 시작 전에** 쓴 것이 좋았다. 클립보드 경로 선택의 근거(dev는 secure context, 프로덕션은 아님)를 그릴링 중에 확정해 뒀더니, 구현 중에 "그냥 `navigator.clipboard` 쓸까"로 흔들릴 여지가 없었다.

## 미해결 / 후속 후보
- **mermaid 블록에는 복사 버튼이 없다.** 이번 비목표였고, 원문은 `data-mermaid`에 그대로 있으므로 원하면 별도 과제로 붙일 수 있다. 다만 삽입 지점과 셀렉터가 `<pre>` 경로와 갈라지고 SVG 위에 버튼을 올리는 스타일링이 따로 필요하다.
- **hover 표시는 하네스가 재지 못한다.** CSS `:hover`를 프로그래밍으로 만들 수 없어 "기본 상태에서 `opacity: 0`"까지만 실측했다. 실제로 hover 시 드러나는지는 사람 확인으로 메웠다.
